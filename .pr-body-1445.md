Closes #1445

## What changed
Added pure-CSS edge fade to `.tab-bar` element in `src/dashboard/static/index.html` using the two-background-attachment trick with linear gradients. The fade creates a visual affordance (semi-transparent dark overlay) on the right edge that indicates scrollable content to the user.

## Why
Users landing on the Portfolio tab on mobile (375px) have no visual cue that more tabs (e.g., Config) exist off-screen to the right until they swipe. The fade provides this affordance per the design spec (issue #816) recommendation, improving Clarity without blocking content or requiring JavaScript changes.

## How to test
1. Open the dashboard in Chrome DevTools device toolbar at 375px width
2. Navigate to any tab (Portfolio works well)
3. Observe a subtle dark fade gradient on the right edge of the tab bar
4. Swipe/scroll the tab bar to the right
5. As you scroll, the fade should gradually disappear (because the gradient scrolls with content)
6. When scrolled all the way to Config tab, fade should be gone
7. Test at desktop (≥1280px): verify no fade appears (tabs don't overflow)
8. Verify theme toggle (light/dark) works correctly with the overlay color

Visual verification: The fade is subtle but visible—it creates a ~40px gradient from transparent (left) to rgba(0,0,0,0.15) (right), layered on top of the native scrollbar.

## How to deploy
No deploy needed—CSS-only change, no backend/database/config modifications.

## Trade-offs
- The semi-transparent overlay (rgba(0,0,0,0.15)) is tuned for the dark theme and appears slightly darker in light theme. Both are acceptable per accessibility guidelines (does not rely on color alone; native scrollbar still provides affordance).
- Gradient is 40px wide—this is a balance between visibility and not obscuring the last visible tab. Can be adjusted if feedback suggests a different width.
